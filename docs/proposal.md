# 社内文書検索AI（RAG）提案書

作成日：2026年8月19日  
対象：株式会社テックブリッジ（従業員50名）

## 1. ご提案の概要

社内に分散している文書を検索し、質問に対して関連する文書の内容を根拠付きで回答する社内文書検索AIを構築します。

まずは、2週間で利用価値を確認できるMVP（最小限の実用版）を作成します。MVPでは対象範囲を「全部署が閲覧できる、文字情報を含むPDF」に限定し、機密文書の部署別アクセス制御や外部サービス連携は次の段階で追加します。

## 2. 現状の課題

- PDF 200本、Word 150本、Confluence 300ページの社内情報が分散している
- 従業員50名が必要な情報を探すために、1人あたり月約5時間を使っている
- 新入社員が先輩に質問する機会が多く、教える側の負担も大きい
- 文書を検索しても、どの資料を根拠にした回答なのか確認しにくい

## 3. 提案する解決方法

RAG（Retrieval-Augmented Generation）を利用します。

RAGは、AIが社内文書を検索し、検索で見つかった関連箇所をもとに回答を作成する仕組みです。AIが文書に書かれていない内容を推測して回答しないよう、回答には出典を表示します。

### 回答までの流れ

```text
PDFを登録
  ↓
PDFから文章を抽出
  ↓
文章を検索しやすい大きさに分割
  ↓
文章をベクトル化してデータベースに保存
  ↓
利用者が質問
  ↓
質問と意味が近い文章を検索
  ↓
検索結果をAIに渡して回答を作成
  ↓
回答と出典（ファイル名・ページ番号）を表示
```

## 4. MVPの範囲（2週間）

初期費用の範囲内で、以下をMVPとして実装します。

- 文字情報を含むPDF最大200本の取り込み
- PDF本文の抽出と基本的なチャンク分割
- ベクトル検索による関連文書の検索
- 関連文書を根拠にしたAI回答の生成
- 回答への出典表示（ファイル名・ページ番号）
- シンプルなチャット画面
- 社内メールドメインによる利用者制限
- 12問のテストによる回答精度・出典表示の確認

### MVPの前提・対象外

- MVPでは、全部署が閲覧可能な共通文書のみを扱います
- 部署限定の機密文書は、部署別アクセス制御が完成するまで登録しません
- 画像だけで構成されたPDFのOCRは対象外です
- 複雑な表の完全な読み取り、パスワード付きPDFは対象外です
- PDFの自動更新ではなく、MVPでは管理者による手動登録・再登録とします
- 既存のActive Directory、Google Workspace、SSOとの本格的な連携は対象外です
- Slackからの利用は対象外です

## 5. Phase 2以降のロードマップ

MVPで土台と利用効果を確認した後、以下を追加で検討します。

- Word文書の取り込み
- Confluenceとの連携
- 部署別アクセス制御（データベースのRLS等を利用）
- Slack Bot連携
- 文書の差分更新パイプライン
- 管理画面（文書管理、質問ログ、利用状況の分析）
- Active Directory、Google Workspace、SSOとの連携
- OCRや複雑な文書レイアウトへの対応
- SOC 2に関する正式な監査対応・追加セキュリティ要件への対応

Phase 2の機能は、MVPの利用状況、セキュリティ審査、正式な要件、追加見積もりを確認した上で優先順位を決定します。

## 6. システム構成

| 層 | 採用候補 | 役割 |
|---|---|---|
| UI / API | Next.js / Vercel | チャット画面とAPIを提供 |
| データベース | Supabase（国内リージョン） | 文書情報、検索用データ、利用者情報を保存 |
| ベクトル検索 | pgvector | 文章の意味の近さを検索 |
| Embedding | 採用するEmbedding APIを確定して利用 | 文書と質問を数値化 |
| 回答生成 | Claude API | 検索結果を根拠に回答を生成 |
| 認証 | Supabase Auth + 社内メールドメイン制限 | 利用者を社内メールアドレスに限定 |

Embedding APIは、利用するサービス、データの取り扱い、費用、リージョン要件を確認した上で1つに確定します。

既存のAWS・社内VPNとの接続が必要な場合は、ネットワーク構成と接続方法を追加確認します。MVPでは、既存AWS・社内VPNとの連携を前提にせず、必要性が確認された場合は別途設計・見積もりとします。

## 7. セキュリティ・データ管理

### MVPで実施すること

- 文書データ、検索用ベクトルデータ、ユーザー情報を国内リージョンに保存する構成を採用
- APIキーや認証情報を環境変数で管理し、ソースコードやGitに含めない
- 社内メールドメインによる利用者制限を行う
- MVPでは全部署共通の文書だけを登録し、部署限定文書を登録しない
- 回答生成時に、検索で取得した文書を根拠として利用する
- 回答に出典を表示する

### 国内保存に関する確認事項

「国内リージョンに保存する」の対象を、次の項目ごとに確認します。

- 文書データ
- ベクトルデータ
- ユーザー情報
- ログ・バックアップ
- AI APIに送信する文章

各サービスの保存場所・バックアップ・ログ・API送信時の取り扱いは、利用サービスの仕様とクライアントのセキュリティ基準を確認して最終決定します。

### SOC 2について

MVPでSOC 2への完全対応や正式な監査を完了するものではありません。MVPでは、国内リージョン、認証、秘密情報管理、出典表示など、セキュリティを考慮した設計を行います。

正式なSOC 2対応、ISO 27001に関する要件、クライアント独自のセキュリティ審査が必要な場合は、要件確認後にPhase 2以降の追加作業として見積もります。

## 8. 回答精度の目標と検証方法

### 目標

- 文書に書かれている質問は、正しい内容を回答する
- 回答には根拠となる出典を付ける
- 文書に書かれていない質問には、推測で回答せず「該当する情報がありません」と回答する
- 12問のテストで、回答内容と出典が正しい割合80％以上を目標とする

### 検証方法

1. 文書に答えが書かれている質問を確認する
2. 複数の文書に関係する質問を確認する
3. 文書に書かれていない質問を確認する
4. 回答内容と出典の正しさを採点する

なお、80％は本番環境での正解率を保証するものではなく、MVP時点でのサンプルテストにおける目標値です。正式な評価方法と合格基準は、クライアントと合意して決定します。

## 11. 追加確認事項

着手前に、以下を確認します。

1. MVPで使用するPDFは、全部署が閲覧可能な共通文書で間違いないか
2. 画像PDFやOCRが必要な文書はあるか
3. 既存のActive Directory、Google Workspace、SSOの利用状況
4. AI APIへの文書送信に関する社内ルール
5. 国内保存の対象範囲（ログ、バックアップ、API送信を含むか）
6. SOC 2、ISO 27001、独自セキュリティ審査の具体的な要件
7. 12問の精度テストにおける合格基準
8. 月額費用に含めるサービスと利用量の上限
9. AWS・社内VPNとの接続がMVPで必要か

## 12. まとめ

まずは、全部署共通のPDFを対象としたRAG検索AIを2週間で構築します。検索結果をもとに回答を生成し、回答の根拠となるファイル名とページ番号を表示します。

部署別アクセス制御、Word・Confluence対応、Slack連携、自動更新、既存認証基盤との連携は、MVPで安全性と利用効果を確認した後、Phase 2として段階的に追加します。

このように、最初からすべての機能を詰め込まず、短期間で使える土台を作り、利用状況と追加要件を確認しながら拡張していく計画です。
